Section 1

Executive Summary

Alert Dining is a mobile platform that helps people with food allergies make safer, more informed choices when dining out. This proposal defines a lean MVP scoped for speed and investor validation — focused on the core loop of allergy profiles, restaurant menus, and personalized ingredient-level risk flagging.

Users create a personal allergy profile from the "Top 14" allergens and browse participating restaurants. Each menu item is displayed with a personalized risk indicator (red / yellow / green) based on the diner's specific allergens. Restaurants sign up, build their menu, tag allergen data, and complete a kitchen questionnaire that feeds into the risk indicator logic.

Access to the app is gated by restaurant invite codes — each participating restaurant receives a unique code and printable QR code. Diners must enter a valid invite code at signup, ensuring the user base is composed of real diners at real restaurants. This creates a controlled launch environment ideal for collecting investor-ready usage data.

Section 4

How It Works

This section describes the primary user flows across the MVP — from diner onboarding to restaurant management to Alert Dining Team operations.

4.1 Diner Flow

1

Download & Enter Invite Code

Diner scans a restaurant's QR code (printed on menus, signage, or table cards) which links to the App Store or Google Play. After downloading, the diner enters the restaurant's invite code at signup. The invite code is required once at account creation and is not needed for subsequent logins.

2

Create Account & Allergy Profile

Diner signs up via email, Apple, or Google. During onboarding, the diner selects allergens from the Top 14 list to build their personal allergy profile.

3

Browse Restaurants

Diner can view all participating restaurants that have been activated by the Alert Dining team via two views: a flat list and an interactive map showing each restaurant as a location pin. Tapping a pin on the map opens that restaurant's menu page directly.

4

Browse Menus

Diner opens a restaurant page and views menu items labeled Green, Yellow, or Red based on their personal allergen profile. Disclaimers remind the diner to confirm with staff.

5

View Item Details

Tapping an item shows a detailed view explaining why it was flagged — specific allergen match, ingredient-level detail (where provided by the restaurant), or cross-contact risk — along with any restaurant notes.

6

Report Inaccurate Information

Diner can flag a menu item as potentially inaccurate by selecting a predefined category (e.g., wrong allergen, missing ingredient, item doesn't exist) and optionally adding a comment. Reports are sent to a shared Alert Dining inbox and displayed in the admin portal.

4.2 Restaurant Admin Flow

1

Sign Up

Restaurant admin creates an account and submits their listing. A unique invite code and printable QR code are auto-generated at signup. The listing enters a pending state until the Alert Dining team activates it.

2

Complete Restaurant Profile

Admin enters business name, address, hours, phone, and website manually.

3

Complete Kitchen Questionnaire

Admin answers cross-contact questions: shared fryer use, dedicated prep areas, ingredient substitution frequency. This directly affects Yellow/Red indicator logic for all items.

4

Build & Tag Menu

Admin creates menu items (name, description, category) and selects one of three transparency paths: Option A — Full Ingredients: enter a complete ingredient list per item, from which allergen flags are derived. Option B — Allergen Tags Only: check allergen boxes from the Top 14 list per item without disclosing full ingredients. Option C — AI-Assisted Ingredient Import: upload an existing recipe book or ingredient list file (PDF, CSV, or spreadsheet); OpenAI reads the file and extracts the ingredient list for each menu item automatically. The restaurant then reviews each item's extracted ingredients on a verification screen, corrects any errors, and confirms before saving. Once verified, the data is stored as a full ingredient list (same as Option A). Full ingredient lists are used internally for risk calculation but are not displayed publicly to diners. Optionally adds item-level notes (e.g., "Pesto contains pine nuts").

5

Publish & Maintain

Menu goes live after the Alert Dining team activates the restaurant. Restaurant admin updates items as needed. "Last updated" timestamp displays to diners.

6

Download QR Code & Invite Code

Restaurant admin can view and download their unique invite code and printable QR code from within the portal. The QR code links to the App Store / Google Play for diners to download the app, and the invite code is entered at signup.

4.3 Alert Dining Team (Management) Flow

The Alert Dining Team uses a lightweight internal admin portal to manage core platform activity during the MVP phase.

1

Activate Restaurants

New restaurant signups appear in a queue. The team reviews submissions and activates restaurants to make them visible to diners. Restaurants remain in a pending state until manually activated.

2

Review Diner Reports

Reports submitted by diners appear in a reports list with the flagged item, category, optional comment, and the diner who submitted it. Reports are also emailed to a shared Alert Dining inbox.

3

Manage Allergen List

Admin manages the master list of recognized allergens. Changes cascade to all tagging interfaces.

4

User Lookup

Admin can search for any diner or restaurant account, view their profile, or deactivate accounts if needed.

Section 7

Risk Indicator Logic

The red / yellow / green system uses three data inputs to generate each indicator:

  • User allergy profile (selected Top 14 allergens)
  • Restaurant kitchen questionnaire flags (cross-contact risk declarations)
  • Menu item allergen data — either derived from a full ingredient list (Option A) or from direct allergen tags (Option B), depending on the path chosen by the restaurant

The Top 14 Allergens (Baseline)

The MVP launches with the following widely recognized allergens. Any additions will be confirmed during the kickoff workshop.

  • Milk
  • Eggs
  • Peanuts
  • Tree nuts
  • Wheat
  • Soy
  • Fish
  • Shellfish (crustaceans)
  • Sesame
  • Mustard
  • Celery
  • Lupin
  • Mollusks
  • Sulfites
IndicatorTrigger Condition
REDItem directly contains a user allergen (via ingredient list or allergen tag), OR restaurant flagged high-risk cross-contact relevant to user allergens
YELLOWAmbiguous or possible cross-contact; restaurant indicated shared environment risk
GREENNo known allergen match based on current restaurant self-reported data (ingredient list or allergen tags)
⚠️ Safety language is always displayed alongside any indicator:
"Based on information provided by the restaurant at the time of your visit."
"Confirm with restaurant staff - ingredients and preparation may change without notice."

Section 13

Assumptions & Open Decisions

13.1 Timeline Transparency

Some aspects of this project may take longer than initially anticipated due to the complexity of third-party integrations, app store review processes, or unforeseen technical challenges. Should this happen, McG Works will be upfront with communication at all times — the client will be informed promptly of any delays, the reasons behind them, and revised timelines before they impact deliverables.

13.2 Assumptions

  • MVP launches with the Top 14 allergens
  • Restaurants choose between full ingredient input or allergen-only tagging per menu item; both paths supported
  • Full ingredient lists entered by restaurants are used internally for risk calculation and are not displayed publicly to diners
  • Risk display uses red / yellow / green only (not percentage scores)
  • Single allergy profile per account (no caregiver/on-behalf distinction in MVP)
  • No payments or subscriptions — all restaurants list for free during the MVP validation period
  • App access is gated by restaurant invite codes; each restaurant receives a unique code and printable QR code at signup
  • Restaurants enter a pending state at signup and are manually activated by the Alert Dining team
  • Restaurant details (name, address, hours, etc.) are entered manually — no Google Places API integration in MVP
  • Admin portal is a lightweight, internal-quality tool — functional but not heavily polished
  • No automated email notifications in MVP — the Alert Dining team handles communications manually
  • Supported file formats for AI ingredient import: PDF, CSV, and XLSX
  • AI ingredient extraction (Option C) is best-effort — restaurant must review and confirm all parsed results on the verification screen before publishing; unverified data cannot be saved
  • Items OpenAI cannot confidently parse from an uploaded file are flagged for manual entry by the restaurant admin
  • Restaurant addresses are geocoded server-side via the Google Geocoding API when a restaurant saves their profile; coordinates are stored in the database and used to render map pins in the diner app
  • Addresses that cannot be geocoded are flagged for manual coordinate entry by the Alert Dining team via the admin portal
  • Location permission is requested from the diner to show their current position on the map; all restaurant pins and map functionality work normally if permission is denied

13.3 Open Decisions (to finalize at kickoff)

  • Confirm Top 14 allergen list
  • Predefined report categories (e.g., wrong allergen, missing ingredient, item doesn't exist) — finalize exact list
  • Specific fields and options for the kitchen questionnaire
  • Analytics provider selection for privacy-safe event tracking
  • Shared Alert Dining email inbox address for report notifications

13.4 Future Capabilities (Post-MVP)

The following features are not in scope for the MVP but have been discussed and can be scoped as a follow-on engagement after validation:

  • GPS-based proximity search & discovery: Location-aware search powered by Google Places API — distance-sorted nearby results, radius filtering, and "restaurants near me" capability. Note: this is distinct from the MVP interactive map view, which displays all active restaurants as pins without proximity filtering or sorting.
  • Event organizer portal: Private, time-bound allergy-aware menus for conferences, catered events, and large gatherings — accessible via QR code and event access code.
  • Restaurant subscriptions: Stripe-powered paid subscription tiers for restaurants, replacing the free MVP listing model.
  • Ratings & enhanced moderation: Diner ratings, enhanced report flow with categorized issue types, admin moderation queue with resolution tracking.
  • Translation cards & wallet passes: Allergy card generator in multiple languages with Apple Wallet and Google Wallet pass support.
  • Family profiles: A single parent/caregiver account managing multiple allergy profiles with a profile switcher.
  • Ads & premium tier: Ad placeholder activation with restaurant and national brand advertising, plus a premium ad-free subscription for diners.
  • Caregiver distinction: Account type toggle for self vs. on-behalf profiles with adjusted legal language.
  • In-app ordering: Ordering directly from within the app at participating restaurants.
